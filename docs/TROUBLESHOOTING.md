2026-09-06 구현 기준입니다. 실패를 숨기거나 자료를 지워 통과시키지 마세요.
앱별 DETAIL, SURVEY_REQUIRED, PUBLISHED_COMMIT과 복구 자료 경로를 함께 확인합니다.

| 보고 | 대응 |
|---|---|
| 다른 PC가 바통 소유 | Finish는 중단. 미게시 작업 보존이 필요한지 먼저 결정한 뒤 Start. 도구가 Start를 자동 실행하지 않음 |
| 원격 Deleted + 로컬 대화 존재 | 재게시·자동 삭제하지 않음. 삭제 수신 전 사본인지, 재등장인지 확인 후 지시 |
| 기존 Active가 로컬에서 설명 없이 소실 | Codex는 부재만으로 삭제를 추론하지 않음. 이전 삭제 조작·기록을 확인하고 사용자가 처리 결정 |
| 양쪽에서 같은 세션 변경 | 공동 게시 중단. 원격이나 로컬 어느 쪽도 자동 선택하지 않음 |
| 실제 구조 불일치 | 자료를 보존하고 사용자 지시로 측량. 앱 버전 번호 변화만으로 차단하지 않음 |
| Start 일부 앱 실패 | 전체 Failure. 전 앱 Start 재실행 필요. 성공분이 남더라도 바통·기준을 정상 완료로 전진시키지 않음 |
| Finish 게시 전 실패 | 시도한 앱의 Cancel 결과 확인. 복구 실패 시 백업을 지우지 않음 |
| 게시 여부 불명 | 원격 조회·네트워크 복구 후 실제 게시 여부부터 확인. 바로 Cancel/재게시/임시 전체 삭제 금지 |
| 게시 성공 후 기준·정리 실패 | 원격 게시를 되돌리지 않음. PUBLISHED_COMMIT과 남은 로컬 완료 작업을 구분해 확인 |

## 앱 종료

Finish는 정상 종료 요청 후 남은 등록 앱 트리만 강제 종료합니다.
창이 사라진 것만으로 종료 성공을 판정하지 않습니다. 호출한 실행기가 앱 트리 안이면 종료 사고를 막기 위해 중단합니다.
Start는 정상 종료만 시도합니다. 실패한 앱을 강제로 닫거나 파일을 밀어 넣지 않습니다.
Finish 성공 뒤 앱은 닫혀 있습니다. Start가 적용을 마치면 앱을 실행합니다.

## Git과 미커밋 변경

Finish는 기존 미커밋 변경을 수집하지만 먼저 별도 커밋을 만들지 않습니다.
모든 앱이 Ready인 뒤 공동 게시 후보를 만듭니다. 실패한 후보 객체가 Git 객체 저장소에 남는 것과
브랜치에 커밋이 추가된 것, 원격에 게시된 것은 서로 다릅니다.
`LOCAL_COMMIT`, `LOCAL_WORK`, `REMOTE_PUBLICATION` 보고를 구분하세요.

실행 중 다른 도구가 작업트리나 index를 바꾸면 덮어쓰지 않고 중단합니다.
미해결 Git 충돌은 사용자가 처리해야 합니다. non-fast-forward는 fetch·앱 재판정 후 최대 3회 게시 시도하며,
인증·네트워크·서버 실패를 세션 충돌로 간주하지 않습니다. force push나 원문 텍스트 병합으로 해결하지 마세요.
Start는 변경을 덮는 작업이므로 clean 작업트리가 필요합니다. Finish와 조건이 다릅니다.

## Archive / Delete 혼동 금지

Vault Archived는 30일 보존이고 앱의 Archived와 별개입니다.
Codex native Archived는 사용자 삭제 경유지입니다. Finish는 검증된 경유 상태를 백업한 다음
앱 원문·관련 DB 투영·인덱스·카탈로그를 제거하고, 기존 게시 세션의 Deleted 기록을 준비합니다.
앱이 최종 삭제까지 끝내 경유 상태도 없다면 부재만 보고 Deleted를 만들 수는 없습니다.

Claude Finish의 Vault Archive는 앱 원본을 지우지 않습니다.
Start가 적용할 때 레코드·본문·배치가 서로 맞아야 합니다. config만 고쳐도 앱 재시작 후 배치가
되살아날 수 있어, 구현은 확인된 LocalStorage 영구 상태까지 백업·검증하며 처리합니다.
직접 SQLite/LevelDB 파일을 임의로 편집하지 마세요.

## 화면과 로그

Start Success는 알려진 구조에 따라 배치·검증·실행까지 완료했다는 뜻입니다.
대화 목록 누락, 잘못된 연결, 다시 생긴 항목이 보이면 성공 로그만으로 정상이라 단정하지 않습니다.
앱이 실제로 읽고 쓰는 상태와 원문 연결을 대조해야 합니다. 무조건 다시 덮거나 업데이트하라는 의미가 아닙니다.

이 대화의 워크벤치 All 실행 로그는 `%LOCALAPPDATA%/MultiAgentCrossReview/Logs`에 있습니다.
실패 시 로그 자동 열기는 All 실행기의 기능입니다. AgentSessionSync 자체는 진행 상황과 결과를 출력합니다.

오래 걸릴 때는 마지막 PROGRESS 단계와 경과 시간을 확인하세요. 현재 전수 읽기가 남아 있습니다.
압축 마커 재사용은 모든 검사 생략과 다릅니다. 개선 후보와 실제 소요 시간은
[마감 보고](IMPLEMENTATION_CLOSEOUT_2026-09-06.md)에 기록했습니다.
